02 — Python & statistics

Does professional curiosity take the weekend off?

Data collected from a public API. If people read about data analysis for work, pageviews should fall at the weekend — and leisure topics should not.

Professional topics lose 32.9% of weekday traffic at the weekend (95% CI −34.5 to −31.3); leisure topics gain 13.1%. The methodological finding matters more: the obvious day-level t-test overstates its confidence by ~15 orders of magnitude, because daily pageviews are autocorrelated.

What I think makes this different

Most portfolios show that the author can get a query to run. These are the things I would want to see if I were hiring.

Three bugs I found in my own work, documented rather than quietly fixed.

  • Non-deterministic segment sizes. Three runs of the same NTILE query on the same data gave 1,006 / 1,003 / 1,029 customers, because ties in a non-total ORDER BY get placed arbitrarily under parallel execution. I caught it because the dashboard disagreed with the README.
  • A filter applied to revenue but not refunds. A price-typo exclusion was gated on one measure and not the other, producing customers with negative six-figure lifetime value who looked like ordinary low-value customers.
  • A docstring that was backwards. It claimed a sample-size shortcut was anti-conservative. It is conservative — p(1−p) is concave. A test caught it.

Results that argue against me. The optimisation study reports that two of three rewrites stop paying at scale, and that one produces a query plan identical to the version it was meant to improve. The churn model's top-decile lift is 1.50x, which looks weak until you note the ceiling at a 57% base rate is 1.74x — so the write-up explains the ceiling instead of hiding the number.

Claims that are executable. One test asserts the hand-written SQL and the dbt project agree to the naira. Another validates every hand-rolled statistic against statsmodels and scipy. Nothing says "I de-duplicated the data" without a test proving it.

Decisions, with their costs. Returns are reported separately rather than netted off silently; price outliers are flagged, not overwritten; orphaned orders keep their revenue but leave the per-customer averages. Each choice is stated once, in one place, with what it gives up.

A note on the data

The warehouse is synthetic, generated deterministically with a fixed seed and carrying eight deliberately planted data quality faults. That means every project runs the moment you clone the repo — no credentials, no large download — and the cleaning decisions can be checked against known ground truth. The cost is that no business finding describes a real company, and each project says so at the top. Project 2 ships a working client for a real public API; one command swaps its fixture for live data.
